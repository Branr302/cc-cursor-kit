# 对照开源吸收笔记

更新：2026-09-03  
原则：上游只走官方 **Cursor SDK**。不接未文档化 Connect。  
本 kit：**仅 adapter**；`proxy/`（agent ask 文本桥）已废弃删除。

## 本 kit

```
Claude Code
  → 127.0.0.1:4011 /v1/messages
  → Cursor SDK Agent + customTools（完整 input_schema）
  → 结构化 tool_use；会合回 CC 本地执行
  → 真 SSE
```

- 鉴权：`CURSOR_API_KEY`
- 默认模型：`grok-4.6`
- 启动：`bin/cc`

## 为何去掉 proxy

- 每轮 fork `agent`、文本 JSON 仿真 tool_use → 慢、易错、难续聊  
- 与 adapter 双轨对称加功能不可持续  
- SDK customTools 已覆盖「CC 执行工具、Cursor 只推理」的合同

## 对照表

- **[starhunt/star-cliproxy](https://github.com/starhunt/star-cliproxy)** — cli subprocess 形态；本 kit 早期 proxy 近此，现已用 SDK 取代。  
- **[BerriAI/litellm](https://github.com/BerriAI/litellm)** — Messages/SSE/`count_tokens` 形状可借；快靠现成推理 HTTP。  
- **[raine/claude-code-proxy](https://github.com/raine/claude-code-proxy)** — 只吸收公开开关；**不实现** Connect/Bidi。  
- **[musistudio/claude-code-router](https://github.com/musistudio/claude-code-router)** — 分流叙事。  
- **[HosheaLi/dsv4-cc-proxy](https://github.com/HosheaLi/dsv4-cc-proxy)** — SSE 清洗；上游官方 HTTP ≠ SDK。

## 明确不做

私有接口、双执行器、复活 proxy、截断 CC 本地对话压 context%。
